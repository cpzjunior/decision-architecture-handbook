# Decision Architecture Guide

The Decision Architecture Guide proposes a practical way to structure, understand, document, and evolve decisions across different contexts.

Defining a software architecture, managing a project, validating a startup, transforming an organization, or making a personal decision may seem like distinct problems. Yet all of them require dealing with context, objectives, constraints, alternatives, uncertainties, evidence, choices, and consequences. What changes is the meaning of these elements and the way the decision evolves.

The frameworks we use in our daily work reveal this convergence. PMBOK organizes the decisions and actions required to manage projects. TOGAF structures the evolution between architectural states, connecting the current situation, future vision, gaps, transition, and governance. arc42 documents the structure and decisions of a software architecture. Lean Startup turns hypotheses into experiments, evidence, and learning. ADR preserves the context, reasoning, and consequences of architectural decisions.

These approaches are not interchangeable, nor do they need to be. The point is something else: their concepts can be abstracted from their original contexts. The reasoning around the current state and desired state can help structure a business transformation. Experimentation can guide a personal decision. Decision records can improve management. The analysis of constraints, alternatives, and consequences can be useful both in solution architecture and entrepreneurship. The cross-context applicability lies in the concepts, not in the frameworks.

The guide starts from this perspective without proposing yet another universal framework. Its purpose is to provide a layer of understanding that comes before the choice of methods: recognize the structure of the decision, understand what needs to evolve, and then use the practices most appropriate to the context.

This simplicity is intentional. The number of frameworks, methods, techniques, and alternatives available has created a paradox of choice: deciding how to decide can become as complex as the problem itself. For this reason, the Decision Architecture Guide is practical and straight to the point. It seeks to provide a common language for navigating this complexity without turning decisions into recipes.

The context changes, the tools change, and decisions evolve. The structure that allows us to understand them, however, can be recognized across different situations.

This is an open and evolving project, developed in this repository as concepts, examples, and learnings are incorporated.

## AI-readable content

The repository is intentionally available for indexing and processing by search engines, AI systems, and other automated tools.

The `ai.md` files contain compressed representations of the articles, preserving their main ideas and arguments while reducing the amount of text required to process them.

They are written in English because English is predominant in the training data and ecosystem of many large language models. Using a compressed English representation can reduce token usage and, consequently, processing and API costs.

The `ai.md` files are derived representations. The `pt-BR.md` file remains the original and canonical source.
