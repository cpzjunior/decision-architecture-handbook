# Contribuyendo

Las contribuciones a la Guía de Arquitectura de Decisión son bienvenidas.

El proyecto es abierto y evolutivo. Las contribuciones pueden incluir mejoras al contenido existente, nuevos conceptos, ejemplos prácticos, referencias, traducciones, correcciones y perspectivas críticas.

## Issues

Utiliza las issues para proponer ideas, discutir problemas o sugerir cambios relevantes.

Siempre que sea posible, presenta:

* Contexto y motivación
* Cambio propuesto
* Ejemplos o referencias relevantes

## Pull Requests

Mantén los pull requests enfocados y explica qué se modificó y por qué.

Para cambios relevantes, abre una issue antes para discutir la propuesta.

## Directrices de Contenido

Las contribuciones deben:

* Centrarse en conceptos, en lugar de prescribir una metodología universal.
* Hacer explícitos el contexto, las premisas y las restricciones.
* Diferenciar conceptos de frameworks o métodos específicos.
* Evidenciar incertidumbres y trade-offs cuando sean relevantes.
* Priorizar ejemplos concretos y referencias confiables.

El objetivo es desarrollar un lenguaje común para comprender decisiones en diferentes contextos, y no crear otro framework universal.

## Discusiones

Las diferentes perspectivas son bienvenidas. Critica ideas, premisas y argumentos, no a las personas, y mantén las discusiones constructivas y basadas en evidencias.
